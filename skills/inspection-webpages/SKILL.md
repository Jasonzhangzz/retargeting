# 可视化核对网页

将真实数据做成可供检查的网页，复用已接受的 Shadow Hand → Wuji2 页面设计。风格和交互可迁移到其他机器人、算法、实验或数据；无需保留手模型、抓型、CUDA 或 MuJoCo 依赖。

## 快速开始

1. 阅读用户给定的结果文件和现有数据加载代码，确认页面要帮助判断的具体问题。已有数据足够时直接实施；复用生产数据和计算方法，避免为页面另造一套结论。
2. 阅读 [references/design.md](references/design.md) 保持视觉风格。需要 Plotly 数据驱动页面时，阅读 [references/data-contract.md](references/data-contract.md)，从随附模板开始；已有 React/Vue 项目则迁移设计变量和交互，不强行改成独立 HTML。
3. 写轻量 adapter，将真实结果转换成数据合同。案例、阶段、方法、图层均由实际数据决定。比较场景优先并排；单视图也可使用同一风格，不为凑布局制造第二套数据。
4. 使用下列生成器输出页面；它内嵌数据和 Plotly，生成可离线打开的单个 HTML。主题、标题、列定义、视图数、指标和案例由输入 JSON 控制。

```bash
# 选择能 import plotly 的现有 Python 环境。
python <skill-dir>/scripts/build_page.py --data inspector.json --output output/review/index.html

# 先查看可运行示例；示例有显式标记，不得作为真实分析结果交付。
python <skill-dir>/scripts/build_page.py --demo --output /tmp/inspection-demo/index.html

# 环境没有 Python Plotly 时，使用已有的官方 Plotly JS 文件。
python <skill-dir>/scripts/build_page.py --data inspector.json --plotly-js /path/to/plotly.min.js --output output/review/index.html
```

脚本只负责展示和结构校验，不运行领域求解器，也不安装依赖或发布网页。超大几何可保留设计并改成共享网格 / 分块加载；没有必要为普通页面引入后端。

## 保留的设计与交互

- 浅灰绿色背景、深青色正文、白色细边框面板、克制的小圆角；标题略带衬线感，编号 / 坐标用等宽字体。
- 信息顺序：标题与说明 → 紧凑工具栏 → 分类图例 → 主要视图 → 当前状态说明 → 少量关键指标 → 可追溯明细 / 来源。
- 多案例可切换；原始 / 映射 / 调整后等阶段有明确名称。一个阶段不能冒充另一个阶段的结果。
- 同一对象跨视图使用稳定的编号和颜色；表格行可联动高亮。3D 对照使用一致单位和比例，支持同步视角、预设视角、隐藏 / 透明表面，以及按需显示法向和骨架。
- 删除无数据支撑的控件与指标。只有单案例或单阶段时，模板自动隐藏多余选择器；2D 图隐藏 3D 控件。

## 比较可信度

对比姿态或形状时使用固定的公共参照系，保留真实尺寸；不要逐帧单独归一化掩盖差异。坐标变换应保持正确手性。领域 adapter 负责单位、参照系、来源和指标定义，模板负责显示。颜色只是分类线索，编号和文字仍需可读。

误差标色须说明阈值与含义；显示偏差不等于宣称物理接触成功或算法正确。缺失项明确显示为空 / 不可用，不能用示例或其他阶段悄悄补齐。正文写检查者需要理解的区别；哈希、文件路径等放来源或导出数据中。

## 验证与交付

检查生成器及适配数据的实际行为：案例和阶段覆盖、有限数值、左右数量与编号对应、单位和比例一致。3D 表面查询点还应核对原始索引 / 坐标；不要只检查 HTML 语法。

可用浏览器时打开页面，检查首屏、至少一个非默认案例、阶段切换、表格高亮和适用的显示开关。数值 / 脚本检查与浏览器实测分别报告；浏览器不可用时不要宣称已视觉验收。静态预览可用现有绘图或渲染工具生成，不是每次任务的必选产物。

交付实际 HTML 链接和简短使用方法，需要时附数据 / 核对结果。仅当用户希望立即浏览时启动本地服务，默认绑定 `127.0.0.1` 并确认可访问；未经请求不要发布到公网。
